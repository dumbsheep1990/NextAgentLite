# 2025-09-21 优化更新：智能体工作室与工作流集成总结

本文档汇总本日围绕 Unla 集成、统一模型网关（9050）、MCP/API 工具、以及智能体工作流与工作室（Studio）相关的优化与实现。所有条目均按“优化”表述。

## 已完成（优化）
- 统一工作室页面（Agent Studio）
  - 新增路由 `/app/agent/studio`，作为单/团队智能体创建后的统一落点页面。
  - 结构：左侧会话占位 + 中间对话测试 + 右侧完整配置（头像、名称/描述/开场白/空回复、关键词分析、TTS、知识库、元数据、系统提示词、相似度阈值/权重、TopN、多轮优化、使用知识自问、推理、Rerank/CrossSearch 预留、聊天模型、向量模型 Provider→Model、温度/TopP/最大token）。
  - 保存创建：携带 `templateId` 进入时，保存走 `/user-agents/create`，并在 `custom_config.resources` 写入知识库/向量模型等；保存成功跳转到 `?agentId` 的工作室页，可即时对话测试。

- 工作流能力集成（后端）
  - 新增最小工作流引擎（异步生成器 + SSE 事件流）：`service/workflows/workflow_engine.py`。
  - 默认“工具编排”工作流：`service/workflows/tool_orchestration.py`
    - 步骤：准备（创建 Agent 并挂载工具）→ 计划（可选）→ 执行（优先异步 arun）。
  - 新增工作流运行接口（SSE）：`POST /api/v1/workflows/run`，事件：`workflow_start/step_start/step_event/step_end/workflow_end/step_error/workflow_error`。

- 工具统一与目录持久化（9050）
  - 统一执行入口：`POST /tools/execute` 支持 `mcp:{server}:{tool}`、`api:{config}:{tool}` 等统一调用。
  - 统一工具目录：`GET /tools/catalog` 与 `GET /tools/functions`（OpenAI 函数描述导出），优先读取持久化数据，回退动态生成。
  - 目录持久化新表 `tool_catalog`（AutoMigrate），新增 `POST /admin/sync-tools-catalog` 自动聚合 MCP 运行时/注册表与 API-Tools 缓存，生成 JSON Schema（最小版：path/query/headers/body = object）。

- Unla 嵌入与鉴权放宽（开发/内嵌态）
  - 5234 增加本机/嵌入模式放行能力，避免 iframe 场景频繁 401（保留生产开关建议）。
  - MCP Registry：`/api/mcp/registry` 提供注册/心跳/查询；9050 可镜像注册（设置 `UNLA_APISERVER_BASE` 时）。

- 前端工具页（Unla Web）
  - MCP 工具页：切换到 9050 运行时；卡片“启动/停止/重启/查看工具”，状态徽章与按钮视觉收敛；移除 5235 直连依赖。
  - API 工具页：对接 9050 `/api-tools/*`，卡片展示绑定 HTTP 服务与路由，可在线测试。
  - 网关配置 UI 文案统一（“工具”→“API”）。

- 模型与选择体验
  - 创建向导模型下拉：白底、按厂商分组（OptGroup），选中仅显示模型名；过滤 `string` 占位。
  - `Max Tokens` 动态上限随模型 context_length（无数据默认 4000），越界自动回退。

- 智能体工具清单（后端）
  - 合并来源：内置 + MCP + API + 自定义，统一输出/去重/排序。
  - 内置工具导入：`POST /api/v1/user-agents/tools/import-builtin`，读取 `docs/agno-tools/builtin-tools.json`（无则兜底两项：reasoning、duckduckgo）。

## 待办（优先事项）
1) Unla 模型页默认设置与 9050 完整打通
   - `llm-settings.tsx` 统一从 9050 获取默认模型与可用模型列表（当前混用 provider API 与 9050）。
   - 设置默认失败时，需要更明显的错误详情提示。

2) /tools/execute 校验增强（9050）
   - 现有 JSON Schema 为最小校验；补充 `oneOf/enum/pattern/array items` 等；错误结构统一化。

3) 工作流持久化
   - 新表 `workflow_sessions`（id, user_id, agent_name, state_json, status, last_step, created_at, updated_at），支持断点续跑与恢复。

4) 工具节点注入与真实检索接入
   - builder 中将用户选择的 MCP/API 工具节点编排到“知识库/图谱”流程合适位置；接入真实的检索/图谱调用逻辑。

5) 安全与开关
   - 9050 写接口与 5234 本机放行增加显式开关/白名单，生产默认关闭。

## 已知注意点
- 部分供应商（如 SiliconFlow/Qwen）在“模型原生 tools 协议”兼容性存在差异，默认关闭原生 tools，优先走本地 ReAct 工具链（可通过环境变量切换）。
- Unla Web 获取模型数据与 9050 的默认/启用信息存在来源差异，后续建议统一数据源（优先 9050）。
- MCP stdio 类工具依赖宿主 Node/npm/npx 环境；9050 仅管理运行与 REST 调用，对外协议仍由 5235 网关负责（后续可评估整合）。
