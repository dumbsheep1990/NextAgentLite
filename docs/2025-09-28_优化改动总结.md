# 2025-09-28 优化改动总结（Agentic Search / 流式输出 / QA 关闭强约束）

本文档记录 2025-09-28 当日完成的后端与前端优化改动，涵盖 Agentic Search（意图识别与检索规划）、检索与路由强约束（关闭 QA 后不再检索 QA）、9050 真流式接入、步骤气泡动效与位置优化、Embedding 模型一致性、数据库事件循环稳定性，以及高级配置（总结输出风格）等方面。

## 概述
- 新增工作流意图识别步骤（step_intent），将用户 Query 分类为 summary / howto / compare / list / fact / entity 等意图，并据此设置检索策略与输出风格。
- 关闭 QA 检索时，任何路径（工作流检索、工具链检索、加权检索）均不会触发 QA 路径（多层兜底与强约束）。
- 对接 9050 `/v1/chat/completions?stream=true` 真正的流式输出；前端逐 token 刷新，步骤气泡只保留一条并展示执行态。
- 统一 Embedding 模型解析（优先用集合绑定、再环境兜底），规避历史旧模型误用。
- 解决 asyncpg 事件循环关闭报错，将 PG 向量检索 SQL 切换为“同步会话 + 线程执行”。
- 高级配置新增“总结输出风格”参数，面板可调并透传到后端控制输出结构。

---

## 1. Agentic Search（意图识别 + 策略规划）
- 新增步骤 `step_intent`（位于 plan 与 retrieve 之间）：
  - 轻规则优先（summary/compare/howto/list 关键词 → 文档 only；很短的“什么/是谁” → fact）。
  - 不确定时调用 9050 小提示 LLM 分类（返回 JSON：intent / need_qa / strategy / top_k / keywords）。
  - 将结果翻译为 `filters.search`:
    - summary/howto/compare/list → include_documents=true、include_qa_datasets=false。
    - fact → include_documents=true、include_qa_datasets=need_qa（若面板关闭 QA，后续层覆盖为 false）。
  - 写回 `ctx.vars['intent']`、`ctx.vars['keywords']`，并可覆盖 `top_n`（默认 8，≤12）。
- 文件：`lite-backend/service/workflows/tool_orchestration.py`

## 2. 检索与路由（关闭 QA 强约束）
- 工作流执行前（`step_prepare`）同步检索策略到工具链：
  - 解析 `filters.search.include_documents / include_qa_datasets`，推导 `papers_only / qa_only / all` 并同步到 `CustomKnowledgeTools`。
  - 同步 `collection_id` 与运行期开关 `_runtime_search_flags`（工具链内部优先读取）。
- 智能检索层尊重 only/exclude 开关（最高优先级）：
  - `only_qa_dataset=true` → 仅 QA；`exclude_qa_dataset=true` → 强制禁用 QA（覆盖 include_*）。
  - 文件：`lite-backend/service/intelligent_retrieval_service.py`。
- 工具链内部优先读取运行期开关（最终覆盖 actual_mode）：
  - 文件：`lite-backend/service/agent_service.py`。

## 3. 9050 真流式 & 步骤气泡优化
- execute 阶段接入 9050 流式：
  - `POST /v1/chat/completions` with `stream=true`，逐行解析 `data: {...}`，提取 `choices[0].delta.content`（或 message.content）为 token。
  - 每个 token 通过 SSE 推送 `step_event`（stage=execute, status=answering, delta=...）。
- 前端渲染：
  - 仅**一条**蓝色步骤气泡，显示执行态：`执行中 …` → `回答中 …` → `回答完毕`；不随 token 叠加。
  - 气泡左侧对齐，横向省略号动效（processing/answering）与淡入动画。
  - 文件：`lite-qa/src/pages/agent/AgentStudioPage.tsx / .css`。

## 4. 输出风格：总结类“基于资料的归纳陈述”
- 当意图为 summary/howto/compare/list 时：
  - 提示词守卫强调“基于资料进行归纳，避免逐字复制，可适度引用并标注来源”。
  - 输出偏好（可配置）：
    - 整体摘要 ≤ intro_max_chars（默认 150）。
    - 关键要点 points_min–points_max 条（默认 3–6），每条 ≤ point_max_chars（默认 80）。
    - 引用与来源 ≤ sources_max（默认 3）。
- 非总结类：资料≥200 字时禁止“未找到相关资料”的模板式回答；资料不足时可明示“未找到”。
- 文件：`lite-backend/service/workflows/tool_orchestration.py`（`_render_prompt`/`step_execute`）。

## 5. Embedding 模型一致性
- 统一解析：优先用“集合绑定的 embedding 模型”，若无则 `EMB_FORCE_MODEL_ID`，否则 `EMB_FALLBACK_MODEL_ID`（默认 `Qwen/Qwen3-Embedding-0.6B`）。
- 短名自动补厂商前缀（如 `text-embedding-v4 → alibaba/text-embedding-v4`）。
- 文件：`embedding_service.py`、`intelligent_retrieval_service.py`、`agent_service.py`。

## 6. 数据库稳定性（asyncpg 与事件循环）
- 将向量检索的 PG SQL 执行改为“同步会话 + 线程执行”，避免 asyncpg 在关闭路径报 `Event loop is closed`、`got result for unknown protocol state`。
- 工具链内部避免替换/关闭主事件循环：在线程内 `asyncio.run(...)` 执行异步解析，带回结果。
- 新增 `get_sync_session`（同步会话获取器）。
- 文件：
  - `lite-backend/service/hybrid_search_service.py`（`_pg_vector_search`）
  - `lite-backend/service/agent_service.py`（集合模型解析）
  - `lite-backend/db/database.py`（`get_sync_session`）

## 7. 高级配置（前端）
- 新增“总结输出风格（Agentic Search）”参数（除通用问答智能体外）：
  - `intro_max_chars`（默认 150）、`point_max_chars`（默认 80）、`points_min/max`（默认 3–6）、`sources_max`（默认 3）。
  - 运行时透传 `summary_prefs`，草稿/导出持久化到 `custom_config.summary_prefs`。
- 恢复 HiRAG 检索开关（实验/占位）。
- 文件：`lite-qa/src/pages/agent/studio/AdvancedSettingsSection.tsx` / `AgentStudioPage.tsx`。

## 8. 待跟进

- 如关闭 QA 后仍偶见 QA 命中，可在 `weighted_retrieval_service` 直接短路：`exclude_qa_dataset=true` 时不构造 QA 任务。
