**NextAgentLite 优化变更总结（2025-09-22）**

- 目标
  - 优化检索与召回链路（由模拟切换为真实混合检索）
  - 完成场景化（通用/政策/学术/企业）元数据提取的端到端接线
  - 提供索引初始化与集合级重推工具，提升排障与可运维性
  - 前端增加“元数据”展示、检索范围控制与召回可视化，提升可观察性

**后端优化**

- 检索由模拟改为真实混合检索
  - 调整端点（由Mock→真实）
    - POST `/api/v1/knowledge/search/intelligent`：调用混合检索服务（向量+关键词），支持 `filters/collection_id/use_rerank`
    - POST `/api/v1/knowledge/test/retrieval`：复用混合检索返回简化结果（非Mock）
    - 文件：`lite-backend/api/endpoints/knowledge_search.py`
  - 检索服务（HybridSearch）
    - 生成查询向量，ES上执行 `mat_qa_chunks` 检索，向量（general_embedding）+关键词组合，分数归一化与噪声过滤，可选Rerank
    - 新增 ensure_index（创建/重建ES索引及映射）
    - 文件：`lite-backend/service/hybrid_search_service.py`

- ES 写入对齐与稳健性
  - 将写入索引由 `document_chunks` 对齐为 `mat_qa_chunks`
  - 将向量字段由 `embedding` 对齐为 `general_embedding`
  - 写入前强制将向量元素转换为 `float[]`，避免被动态映射为 `long`
  - 文件：`lite-backend/service/knowledge_service.py`（`_save_vectors_to_es`）

- ES 初始化与集合重推工具
  - 新增端点
    - POST `/api/v1/knowledge/search/init-index`：初始化/重建 `mat_qa_chunks`（dense_vector 映射，dims 可配）
    - POST `/api/v1/knowledge/search/reindex-collection`：指定集合重推分块向量到 ES（可选重建索引、limit、dims）
    - 文件：`lite-backend/api/endpoints/knowledge_search.py`
  - 新增脚本
    - `scripts/es_init_index.py`：命令行初始化/重建索引（可配置 host/dims/force）

- 场景化元数据提取（对接并落库）
  - 文档处理阶段接线（不影响主流程，异常不阻塞）
    - 分块向量化后，根据文档所属知识库的 `metadata_template` 选择系统模板，调用 `MetadataExtractionService` 提取结构化元数据
    - 落库字段：`metadata_template_id`、`structured_metadata`、`metadata_extraction_status`、`metadata_extraction_log`
    - 文件：`lite-backend/service/knowledge_service.py`（`extract_and_vectorize_document`）
  - 单文档/批量提取API链路
    - 新增方法：`extract_metadata_for_document`、`bulk_extract_metadata_for_collection`
    - 新增端点：POST `/api/v1/collections/{collection_id}/metadata-extraction/run`
    - 文件：`lite-backend/service/knowledge_service.py`、`lite-backend/api/endpoints/knowledge_collection.py`

- 文件上传切分配置应用对齐（元数据写入修正）
  - 将上传时前端传入的切分相关参数映射至 `document_metadata.processing_config`（后续切分读取该配置生效）
  - 映射：`chunkingConfigId → chunking_config_id`、`customChunkSize → custom_chunk_size`、`customChunkOverlap → custom_chunk_overlap`
  - 文件：`lite-backend/api/endpoints/knowledge_documents.py`

- 模板数据与表结构补齐（MCP）
  - 通过 MCP 对齐 `metadata_templates` 表字段并注入系统默认模板（general/policy/academic/enterprise）
  - 新增列以对齐模型字段：`template_type`、`schema_definition`、`extraction_config`、`display_config`、`search_config`
  - 注入 4 个系统模板，`is_system=true, is_active=true`
  - 说明：历史文档此前无 `structured_metadata`，新处理或补提后会自动落库

**前端优化**

- 检索测试页增强
  - 初始化索引 UI：设置向量维度（默认1024）与强制重建，调用 `/knowledge/search/init-index`
  - 仅检索当前知识库：开关控制检索范围（传 `collectionId`）
  - 显示检索范围提示（全局/当前知识库：名称/ID）
  - 结果召回统计：类型分布（文档/QA），Top 3 高分结果（标题/来源/分数）
  - 文件：`lite-qa/src/components/knowledge/RetrievalTest.tsx`、`lite-qa/src/pages/knowledge/KnowledgePageClean.tsx`、`lite-qa/src/services/knowledgeService.ts`

- 文档列表页面增强
  - 新增“元数据”列：展示“已提取/未提取”，支持 JSON 预览 Modal（含模板ID）
  - 工具栏新增“提取元数据”按钮（批量调用 `/collections/{id}/metadata-extraction/run`）
  - 工具栏新增“一键重建索引并重推ES”按钮（先重建索引，再重推当前库 chunks）
  - 文件：`lite-qa/src/components/knowledge/DocumentList.tsx`、`lite-qa/src/services/collectionService.ts`、`lite-qa/src/services/knowledgeService.ts`

- 类型补充
  - `KnowledgeDocument` 类型新增：`metadataTemplateId?`、`structuredMetadata?`、`metadataExtractionStatus?`
  - 文件：`lite-qa/src/types/index.ts`

**可运维性提升**

- 初始化/重建索引（任选其一）
  - 前端：检索测试页 → “初始化检索索引”（dims=1024，勾选强制重建）
  - 后端：`POST /api/v1/knowledge/search/init-index`（`{"force":true,"dims":1024}`）
  - 脚本：`python scripts/es_init_index.py --host http://localhost:9200 --dims 1024 --force`

- 集合级重推
  - 前端：文档列表 → “重建索引并重推ES”
  - 后端：`POST /api/v1/knowledge/search/reindex-collection`（可选 `recreate_index/dims/limit`）

- 批量提取元数据
  - 前端：文档列表 → “提取元数据”
  - 后端：`POST /api/v1/collections/{id}/metadata-extraction/run`（默认仅处理 `pending/failed`）

**验证建议**

- ES 映射校验
  - `mat_qa_chunks` 应有 `general_embedding`（dense_vector）及文本/属性字段；若历史错误映射，请先强制重建索引

- 写入验证
  - 上传/处理文档后：ES `GET mat_qa_chunks/_search?q=document_id:<docId>` 应能查到对应 chunks

- 检索验证
  - 检索测试页：开启“仅检索当前知识库”，观察召回数量、Top 3 结果

- 元数据验证
  - DB（MCP）：`SELECT metadata_template_id, structured_metadata IS NOT NULL, metadata_extraction_status FROM knowledge_documents ORDER BY created_at DESC LIMIT 5;`
  - 前端：文档列表“元数据”列显示“已提取”，点击“查看”可展开 JSON

**后续可优化方向**

- 检索测试页：增加分数分布图/分段汇总（可视化召回质量）
- 文档详情页：按场景优化结构化元数据的字段展示（政策：发文机关/文号/日期；学术：作者/期刊/DOI）
- UploadModal：将获取“知识库切分配置”的 fetch 替换为统一 `apiService`
