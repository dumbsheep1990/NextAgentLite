# 今日实现优化总结（2025-09-26）

## 概览
- 今日聚焦三条主线优化：检索与回写一致性、全链路实时进度（SSE）、QA 提取与向量化可观测性，兼顾索引命名可配、ES 写入补齐字段与前后端联动。
- 目标成效：检索“命中为 0”排查更高效、文档与 QA 处理过程“可见可感”、数据回写和删除链路更稳。

## 检索与索引
### 统一索引命名与读写一致
- 集合重向量化回写去除硬编码，改用可配索引名：`hybrid_search_service.index_name`。
- 写 ES 时补写 `collection_id` 到顶层与 `metadata.collection_id`，保证检索过滤一致。
- 代码：`lite-backend/service/collection_revectorize_executor.py`、`lite-backend/service/knowledge_service.py`

### QA 向量索引可配化（pairs）
- 批量回写 `_save_qa_vectors_to_es_batch()` 改为读取配置/环境（`settings.database_elasticsearch.qa_pairs_index` → `ES_QA_PAIRS_INDEX` → 默认），并补写 `collection_id`（通过数据集反查）。
- 单条写入路径已对齐可配逻辑。
- 代码：`lite-backend/service/qa_dataset_service.py`

### 回写接口与诊断
- 初始化索引：`POST /api/v1/knowledge/search/init-index`
- 重新回写集合：`POST /api/v1/knowledge/search/reindex-collection`
- 检索诊断：`POST /api/v1/retrieval/debug`
- 代码：`lite-backend/api/endpoints/knowledge_search.py`、`lite-backend/api/endpoints/retrieval_router.py`

## SSE 实时推送（文档 + QA）
### 统一通道
- 文档处理从旧的 `document_sse` 切换到统一 `unified_sse_manager`，与前端 `/api/v1/sse/document-status/{session_id}` 对齐。
- 广播范围用 `session_id="all"`，保证所有会话都能收到。
- 代码：`lite-backend/service/knowledge_service.py`、`lite-backend/api/routes.py`

### 文档处理阶段化推送（URL → 分块 → 向量化）
- 事件：`task_progress_update`（开始/分块进度）、`task_completed`、`task_failed` + `document_status_update`。
- 字段：`document_id`、`collection_id`、`progress`、`stage/detail`、`task_type=document_processing`。
- 代码：`lite-backend/service/knowledge_service.py`

### QA 提取阶段化推送
- 事件：开始(1%) → 创建数据集(10%) → 生成 QA 完成(60%) → 完成/失败；`task_type=qa_extraction`，附 `document_id`/`dataset_id`。
- 完成后自动触发 QA 向量化（原有逻辑保留），对应事件继续通过 QA 向量化通道推送。
- 代码：`lite-backend/service/unified_qa_extraction_service.py`、`lite-backend/service/qa_dataset_service.py`

### 前端统一监听与渲染
- SSE 单例：`lite-qa/src/services/sseService.ts` 将后端事件分发为 `sse-message`。
- 文档列表：监听 `sse-message`，动态更新卡片进度/状态。
  - 代码：`lite-qa/src/components/knowledge/DocumentList.tsx`
- QA 数据集：监听 `sse-message`，解析 `task_type` 中包含 `qa/qa_dataset/vectorization` 的事件，动态更新总数/已向量化数/进度。
  - 代码：`lite-qa/src/components/knowledge/QADatasetPanel.tsx`

## 清洗与稳定性（延续优化）
- 分块前“专业清洗”多媒体/base64，避免脏数据进入向量化与 QA。
  - 代码：`lite-backend/service/knowledge_service.py`
- QA 超长文本分窗生成，避免 `max_seq_len` 超限。
  - 代码：`lite-backend/service/qa_generation_service_simplified.py`
- 删除解环（FK）顺序化处理，支持强制删除端点。
  - 代码：`lite-backend/api/endpoints/knowledge_documents.py`
- 用户种子端点与启动注入（开发环境辅助）。
  - 代码：`lite-backend/service/user_seed_service.py`、`lite-backend/api/endpoints/auth.py`

## 一致性与可配置
- 索引名统一来源顺序：
  - Chunks：`settings.database_elasticsearch.qa_chunks_index` → `ES_QA_CHUNKS_INDEX` → 默认
  - QA Pairs：`settings.database_elasticsearch.qa_pairs_index` → `ES_QA_PAIRS_INDEX` → 默认
- ES 文档补齐：
  - 顶层 `collection_id` 与 `metadata.collection_id` 全量补齐，保证检索条件一致。

## 验证与操作指南
- 初始化索引：
  - `POST /api/v1/knowledge/search/init-index` 载荷：`{"force": true, "dims": 1024, "indexing": "none"}`
- 回写集合：
  - `POST /api/v1/knowledge/search/reindex-collection` 载荷：`{"collection_id":"<集合ID>","recreate_index":false,"dims":1024}`
- 检索诊断：
  - `POST /api/v1/retrieval/debug` 载荷：`{"query":"NextAgent","collectionId":"<集合ID>","topK":8}`
- 前端观察：
  - 文档上传/URL：文档卡片进度/状态实时变化。
  - 自动 QA 提取：QA 数据集列表实时显示“处理中→完成”与统计。
  - 工作室检索：打开“检索面板”查看命中轨迹（需先写入 ES）。
